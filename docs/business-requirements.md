# Бизнес-требования

> Зафиксировано через интервью skill `grill-me` (2026-08-16) и подтверждено заказчиком. Ничего из этого не додумано сверх того, что было явно решено или прямо помечено как demo-плейсхолдер.

## Контекст продукта

- Sports Cave Barbershop на данный момент — **демонстрационный MVP**, а не сайт реального действующего барбершопа. Продукт планируется показывать барбершопам как готовое решение и продавать позже.
- Реального клиента ещё нет: контактные данные (телефон, адрес) — явные плейсхолдеры, не выдаются за настоящие (телефон использует зарезервированный для вымышленного использования обмен 555).
- Мультитенантность/шаблонизация под разных заказчиков **не проектируется сейчас** — фокус только на Sports Cave. Данные (услуги/мастера) уже вынесены в отдельный слой (`src/data/*.json`), что упрощает будущий рефакторинг в шаблон, но полноценная мультитенантность — сознательно отложенная задача.

## Локация и аудитория

- Одна точка барбершопа, позиционируется на стыке районов **Happy Valley, Gresham и Clackamas** (Oregon, US).
- Целевая аудитория: мужчины, устоявшиеся в жизни (дом, автомобиль), любой расы — не узкая молодёжная субкультура. Отражено в тоне бренда: "Premium Stadium" — сочетание премиальности и спортивной/индустриальной эстетики, без инфантильности.
- Язык интерфейса — только английский.

## Sitemap v1

Четыре страницы, без About/Contact/Gallery/FAQ/Privacy на v1:

1. **Home** (`/`) — hero, тизер услуг, CTA на команду
2. **Services** (`/services`) — полный прайс по категориям
3. **Team** (`/team`, "The Roster") — профили мастеров
4. **Book** (`/book`) — визард бронирования

## Бронирование

- Реализовано полностью **своими силами**, без внешних booking-сервисов (YCLIENTS и т.п.).
- Клиент выбирает: услугу → мастера → дату/время → оставляет контакты (имя, телефон, email опционально).
- Все мастера работают в единых часах салона (нет индивидуального расписания по мастерам на v1).
- **Двойное бронирование физически невозможно**: уникальное ограничение в БД на (мастер, дата, время). Сознательное упрощение v1: проверяется точное совпадение слота, а не пересечение по длительности услуги — см. [architecture.md](./architecture.md#известные-упрощения-v1).
- После успешной брони уходит уведомление в Telegram. Секреты (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) заведены пустыми в `.env.local` — заполняются, когда появится реальный бот. Слой уведомлений спроектирован так, чтобы позже добавить WhatsApp без переделки формы/API.

## Услуги и мастера

- Реального прайса и состава мастеров у барбершопа нет — используются правдоподобные demo-данные, собранные из готовых Stitch-макетов (см. `archive/stitch-mockups/`) и приведённые к единому неймингу.
- Каталог — простые JSON-файлы (`src/data/services.json`, `src/data/masters.json`), редактируются разработчиком через код + деплой. Осознанно без админки на v1, но структура данных не мешает добавить её позже.
- Нужна страница с профилями мастеров; при бронировании клиент обязательно выбирает конкретного мастера.

## Контент и фото

- Реальной фотографии барбершопа/мастеров нет. Используются стилизованные плейсхолдеры (не хотлинк на временные URL из Stitch-макетов — они не гарантированно стабильны и не наши по лицензии).
- Оригиналы Stitch-макетов (HTML, скриншоты, дизайн-система) сохранены в `archive/stitch-mockups/` — не удалять, не редактировать на месте.
- Тексты сайта — написаны/адаптированы нами на основе макетов; правки и финальное утверждение — за заказчиком по мере появления реального контента.
