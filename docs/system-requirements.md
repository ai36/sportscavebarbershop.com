# Системные требования

## Среда выполнения

- Node.js 24.x (см. локальную версию `node -v`; зафиксировать в `package.json#engines`, если появится CI)
- npm как package manager (`package-lock.json` в репозитории — не смешивать с yarn/pnpm)
- Next.js 16 (App Router, Turbopack), React 19, TypeScript 5, Tailwind CSS 4

## Поддержка браузеров/устройств

- Мобильная адаптивность — базовое требование, не второстепенная задача. Проверяется на каждом экране по ходу разработки, а не в конце.
- Актуальные версии Chrome, Safari (включая iOS Safari), Firefox, Edge. Специальной поддержки устаревших браузеров (IE, старые Android WebView) не требуется.
- Ключевые breakpoint'ы дизайн-системы: mobile (по умолчанию), `md:` (Tailwind, ≥768px) для desktop-раскладки — см. [design-system.md](./design-system.md).

## Производительность

- Целимся в стандартные Core Web Vitals для Vercel/Next.js проекта (LCP/INP/CLS в "зелёной" зоне на мобильном 4G-профиле) — формальный бюджет пока не задан, замерять после первого реального деплоя (`vercel-optimize` skill).
- Статические страницы (`/`, `/services`, `/team`, `/book`) должны престатиковаться (`○ Static` в выводе `next build`) — не заводить на них server-side data fetching без необходимости.

## Доступность (a11y)

- Не формализовано целевым уровнем WCAG, но UI обязан пройти ревью через skill `web-design-guidelines` перед объявлением готовым (см. критерии в [business-requirements.md](./business-requirements.md#критерии-готовности-v1)).
- Тёмная тема (единственная — сайт "dark-mode-first" по дизайн-системе) должна сохранять контраст текста над фоном; при полировке проверять `prefers-reduced-motion` для анимаций (`apple-design` / `review-animations` skills).

## Данные и хранение

- **Транзакционные данные** (брони) — Vercel Postgres (Neon), доступ через Drizzle ORM. Требует переменную `POSTGRES_URL` (или `DATABASE_URL` для локальной альтернативной БД) — см. [architecture.md](./architecture.md).
- **Контентный каталог** (услуги, мастера, конфиг сайта) — версионируемые JSON-файлы в репозитории, не в БД.
- Резервное копирование БД — на стороне управляемого сервиса (Vercel/Neon), отдельно не настраивается на v1.

## Секреты и переменные окружения

Полный список — `.env.example` в корне репозитория. На сегодня:

| Переменная           | Назначение                         | Статус                       |
| -------------------- | ---------------------------------- | ---------------------------- |
| `POSTGRES_URL`       | подключение к БД бронирований      | не заполнено — БД не создана |
| `TELEGRAM_BOT_TOKEN` | бот для уведомлений о новой записи | не заполнено — бота ещё нет  |
| `TELEGRAM_CHAT_ID`   | чат, куда слать уведомления        | не заполнено                 |

Секреты **никогда** не коммитятся (`.env.local` в `.gitignore`); публичные аналитические ID (Google Analytics) при подключении оформлять как `NEXT_PUBLIC_*`.

## Деплой

- Целевая платформа — Vercel (skills `deploy-to-vercel`, `vercel-cli-with-tokens`, `vercel-optimize`). Проект в Vercel пока не создан/не связан с этим репозиторием.
- GitHub remote подключён: `git@github.com:ai36/sportscavebarbershop.com.git` (пуш ещё не выполнялся).

## Безопасность

- Все пользовательские данные бронирования (имя/телефон/email) хранятся только в БД проекта; наружу не публикуются.
- API-роуты (`/api/bookings`, `/api/availability`) валидируют вход (принадлежность `serviceId`/`masterId` каталогу, формат даты/времени, попадание времени в реально сгенерированные слоты) до записи в БД.
- Rate limiting/защита от спама на форму бронирования — не реализовано на v1, зафиксировано в [BACKLOG.md](../BACKLOG.md).
